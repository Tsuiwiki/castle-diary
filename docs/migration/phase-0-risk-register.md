# 阶段 0 · 风险登记册（phase-0-risk-register）

> 底稿：DATA-01 的 17 条风险（PWA 端）。本册只列**与原生迁移相关**的风险，PWA 端风险见 DATA-01（仍然有效）。

| # | 风险 | 等级 | 缓解 |
| --- | --- | --- | --- |
| R1 | v2 备份大包导入内存峰值（200 张照片约 110MB JSON，手机端整包 parse 峰值可达 300-500MB） | 高 | 一期限 100MB 内整包 parse + 导入前体积检查提示；二期流式解析（kotlinx.serialization streaming） |
| R2 | 城堡 SVG → Compose Canvas 重画工作量与视觉回归 | 高 | 列原生二期；用截图对比验收；一期用"层数正确的简化城堡"过渡 |
| R3 | KaiTi/楷体字体版权——安卓无该字体，内嵌需授权 | 中 | 改用开源楷体（霞鹜文楷 OFL）或思源宋体；一期先系统衬线字体 |
| R4 | Capacitor 版存量数据（用户已开始在 App 里记）迁移依赖手动导出 | 中 | 导入向导首页明示；Capacitor 版设置页保留导出入口 |
| R5 | 网页版与原生版并行期的功能差异（二期前原生无分册）使用户困惑"数据去哪了" | 中 | 导入器保证全量入库（分册数据入库、界面后到）；文档与引导说明 |
| R6 | 双端并行开发导致备份格式分叉 | 中 | v2 格式冻结：任何一端改格式必须同步 dataCheck.js 与原生校验器，并在 risk-register 登记 |
| R7 | Compose 学习曲线导致一期工期波动 | 中 | UI 按现有 PWA 截图 1:1 复刻，减少设计决策；关键界面先做骨架验收 |
| R8 | Room schema 演进破坏用户数据 | 高 | Migration 强制 + 破坏性迁移禁令 + schema 导出测试（任务书 1.3） |
| R9 | 媒体文件与数据库一致性（写文件成功/写库失败或反之） | 中 | 事务外文件操作采用"先文件后库+孤儿清理任务"（任务书 1.4） |
| R10 | 上架资质时间线（软著 30-60 工作日）阻塞发布 | 低 | 与开发并行启动软著；上架材料清单已备（安卓版/上架准备.md） |
| R11 | 原生版离线定位与"不联网"承诺被无意破坏（如引入崩溃上报 SDK） | 中 | 一期禁止任何联网依赖；release 检查 uses-permission 仅 RECORD_AUDIO |

## PWA 端遗留风险（DATA-01 摘录，仍有效）

- 孤立媒体不清理（导入时检测）→ 原生导入器需做引用可达性检查并出清单；
- localStorage 单键全量写放的写入放大 → 原生 Room 化后自然消除。

# 阶段 0 · 本地安全设计评审（phase-0-security-review）

> 只评审，不定案。任务书 0.7 全部问题逐项覆盖；推荐方案标注，**最终由用户确认**。

## 1. 数据敏感性盘点

- 高敏感：日记正文、孩子照片、录音、生病记录、生日。
- 低敏感：词库、绘本目录、玩具。
- 泄露面：缩略图/缓存（私有目录内，风险低）、日志（严禁输出正文/路径含孩子信息）、备份文件（导出后由用户保管，明文 JSON）。

## 2. 三方案对比

| 维度 | A 私有目录+系统加密（基线） | B 分类加密（媒体+数据库分开处理） | C 统一应用层加密+跨设备恢复 |
| --- | --- | --- | --- |
| 隐私保护 | 依赖 FBE 设备加密+应用沙箱；root/调试下可读 | 数据库与媒体 AES-GCM；比 A 多一层 | 全量 AES-GCM，最高 |
| 实现复杂度 | 低（零代码） | 中（SQLCipher 或自管密钥+媒体流加密） | 高（密钥体系+恢复流程） |
| 性能开销 | 无 | 查询/解密有感知（媒体缩略图变慢） | 明显（全量加解密） |
| 搜索/浏览影响 | 无 | 索引需在明文字段上设计 | 同 B 且更重 |
| 备份恢复复杂度 | 备份文件即明文 v2（现状） | 备份需再加密或导出时解密 | 备份天然密文；**丢密钥=数据永久不可解** |
| 密钥丢失风险 | 无密钥概念 | Keystore 密钥不可导出→换机需走"明文导出"通道 | 同左，且后果更重 |
| 对未来云存储 | 直接兼容（v2 明文） | 需定义密文备份格式 | 端到端加密基础好 |

## 3. 推荐

**一期采用 A**，同时预留 B/C 的接口位（MediaAsset.encryptionVersion 字段已列入映射）。理由：
1. 与隐私承诺一致："数据只存在这台手机"——FBE（Android 7+ 默认全盘加密）+沙箱已满足产品级保护；
2. v2 备份格式保持明文互通，是网页版↔原生版互为安全网的前提；C 方案会破坏这一安全网；
3. 应用锁（PIN+生物识别）已计划实现，覆盖"借手机"场景——这是本产品实际的主要风险面。

## 4. 系统备份行为（已验证/待验证）

- Capacitor 版：已禁云备份、允许设备迁移（data_extraction_rules.xml）——**原生版沿用同一策略**，Auto Backup 排除全部用户数据（验证方式：adb backup 检查，阶段 1 任务 I）。
- 设备迁移（手机对手机）：允许包含数据库与媒体（用户换机体验）。
- 用户主动导出（v2 明文 JSON）与系统备份的区别需在隐私政策中说明（现行隐私政策已覆盖）。

## 5. 密钥与恢复边界（若未来采用 B/C）

- Keystore 密钥不可导出 → 换机恢复只能走明文 v2 导出通道；
- "忘记应用锁密码"= 本地锁，不影响数据（恢复码机制沿用 PWA 设计）；
- 任何加密实现前必须先回答："用户换新手机且无旧机时，如何恢复？"——答不了就不上加密。

## 6. 待用户确认决策

1. 一期是否接受方案 A（推荐）；
2. 应用锁是否一期就要（PWA 已有，建议对齐）；
3. 备份文件是否需要可选密码加密（PWA 现状无；作为 B 方案的一部分后续评估）。
